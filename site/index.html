How to detect Claude in Chrome on your website

Updated November 20, 2026 · verified against Claude in Chrome 1.0.107

Short answer: you can't detect Claude in Chrome from your server. It runs inside the visitor's own Chrome, with their user agent, cookies and IP address. You can detect it with JavaScript in the page, because it leaves three kinds of traces:

1. its on-page overlay (an element on <body> holding a closed shadow root),
2. the event order of its form_input tool (change before input), and
3. keystrokes and clicks with machine timing.

The free, open-source isagent script checks all of them and tells you which form fields Claude filled.

<script src="https://cdn.jsdelivr.net/npm/isagent.js@1/dist/isagent.min.js"></script>
<script>
  const detector = isagent.start({ formField: "agent_detection" });

  if (isagent.isAgent()) {
    // an AI browser agent is (or was) operating on this page
  }
</script>

Why your server can't see Claude in Chrome

Most bot detection starts on the server: user-agent lists such as isbot, IP reputation, TLS fingerprints. None of these work here. Claude in Chrome is a browser extension that drives the visitor's real browser over the Chrome DevTools Protocol. Every request comes from a normal, logged-in Chrome on the visitor's own connection, and the extension sends no identifying header.

What changes is what happens inside the page, and a script running there can see it.

Three ways to detect Claude in Chrome in the page

1. Its overlay element

While Claude works on a tab, it draws an orange glow, its own cursor, a "Claude is working" tag and a Stop button. All of these live in a closed shadow root attached to one attribute-less <div> that the extension appends to <body>. The page can't look inside, but it can see the element itself:

  • it is a div with no attributes and no children, directly under <body>;
  • its computed display is contents;
  • calling attachShadow() on it throws, because a closed root already exists.

The element stays after Claude finishes, so even a script that loads late can tell Claude was there. While Claude is actively working, the Stop button and tag also receive pointer events, so document.elementsFromPoint() at their positions returns the overlay element. That gives you a live "Claude is acting right now" signal.

Why #claude-agent-stop-container stopped working: earlier write-ups suggested querying ids like #claude-agent-stop-container, #claude-agent-glow-border or #claude-agent-animation-styles. Since the overlay moved into a closed shadow root (version 1.0.107), those queries return nothing, even while Claude is on the page. Detecting by structure keeps working. isagent still checks the old ids for older versions.

2. Its form_input tool

To fill a field, Claude's form_input tool sets the value directly, focuses the field, then dispatches an untrusted change event followed by an untrusted input event, both in the same task. Real typing, browser autofill and normal scripts fire input first. The reversed order identifies Claude, and tells you exactly which field it filled. Checkboxes and radios are toggled with a script click(), which is also visible as an untrusted click.

3. Machine-timed typing and clicks

When Claude types with its computer tool, it sends every key-down and key-up through the DevTools Protocol at once. The events are trusted, but each key is held for under a millisecond with no gap between keys. People hold keys for tens of milliseconds. Clicks are similar: the pointer appears on the target in a single jump, with no movement trail, and the button is released within milliseconds.

Measure these with each event's timeStamp, not the time your handler runs. On a busy page, a person's key-down and key-up can wait in the queue and run back to back, which would make them look like a bot.

Which fields did Claude fill?

Knowing that an agent was present is useful; knowing which answers it wrote is better. isagent attributes every field to the method that filled it and sends the result with your form:

{
  "verdict": "agent",
  "agent": "claude-in-chrome",
  "active": true,
  "fields": [
    "input#email[name=\"email\"]:form_input",
    "textarea#message[name=\"message\"]:synthetic-typing"
  ]
}

With formField set, this JSON is added to every FormData built from a form. That covers normal submissions, form.submit() and fetch with new FormData(form). For JSON APIs, send detector.summary(form) yourself.

What to do when you detect it

  • Don't hard-block. Many visitors use Claude in Chrome on purpose. Some generic signals can also come from on-screen keyboards, voice input or password managers.
  • Ask for confirmation of the fields an agent filled, or send a confirmation email before acting on the submission.
  • Review or rate-limit agent submissions on sensitive flows such as sign-ups, payments and reviews.
  • Measure how much of your traffic is agent-driven before deciding on a policy.

The result is generated in the visitor's browser, so treat it as a signal, not proof. A missing result tells you nothing either way.

What can't be detected

  • Reading. Reading the page, taking accessibility snapshots and capturing screenshots leave no trace a page can observe.
  • Background tabs. Claude turns on focus emulation, which makes a background tab look visible and focused.
  • Future versions. Any of these traces could change in a later release. isagent's test suite runs the installed extension's own code to catch that.

Frequently asked questions

Can a website detect Claude in Chrome?

Yes, from JavaScript in the page, but not from the server. Its overlay element, the event order of its form_input tool and the timing of its keystrokes and clicks are all observable.

Does Claude in Chrome have its own user agent?

No. It uses the visitor's normal Chrome user agent and sends no special header, so user-agent checks like isbot don't catch it.

Does this detect ChatGPT agent, Comet or Browser Use?

isagent identifies Claude in Chrome specifically. Other DevTools-driven agents are detected through generic signals: synthetic typing, teleporting clicks, automation globals and published DOM markers.

Is it free?

Yes. isagent is MIT-licensed, has no dependencies, is about 7 KB gzipped and makes no network requests.

How do I test it?

Open the live demo and ask Claude in Chrome to fill in the form. Each field it fills is outlined, along with the method it used.

Get started

npm install isagent.js
import { start, isAgent } from "isagent.js";

const detector = start({
  formField: "agent_detection",
  onDetect: (report) => console.log("Agent detected:", report.agent),
  onFieldFill: ({ element, method }) => element.classList.add("agent-filled"),
});
